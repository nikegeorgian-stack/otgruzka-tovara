## Краткая инструкция сотруднику

1. Откройте «Табель», выберите месяц и свою бригаду.
2. Найдите сотрудника в строке поиска над таблицей (`data-coach="month:employeeSearch"`). Поиск не изменяет данные.
3. Нажмите «Редактировать». В слое «Факт» выберите фактический код дня. Если он совпадает с планом, выбор того же кода всё равно создаёт подтверждение. Для нескольких дней можно использовать существующее выделение ячеек и общий выбор кода.
4. Нажмите «Готово» и проверьте документ: сотрудник, дата, слой, было/стало либо подтверждение факта. Сохраните его. Это локальное проведение; завершение облачной синхронизации проверяйте по существующему индикатору приложения.
5. Если вы ушли со страницы или перезагрузили её до проведения, появится уведомление о черновике. Откройте «Проверка изменений» (`data-coach="month:reviewDraft"`) и решите, сохранить или отменить. Черновик сам не проводится. При конфликте с уже изменёнными данными спорные правки останутся для проверки.
6. Отмена черновика отменяет изменения **кодов дней**. Часы, назначения, переносы и другие отдельные операции сохраняются отдельно. Они не входят в эту кнопку отмены.
7. После проверки всех фактических дней отметьте «Табель сверен» для бригады. Если после этого табель изменится, сверка перестанет считаться актуальной. Старые флажки без подписи содержимого тоже требуют повторной сверки.
8. Закройте месяц. Если программа отказывает, сначала устраните причины из сообщения. После повторного открытия исправьте данные, повторите сверку и закройте месяц заново.

## Важные границы этого пакета

- **Открытый месяц остаётся предварительным расчётом:** совместимый механизм ещё может показывать унаследованный план. Новый контроль запрещает окончательное закрытие без явного факта; это не полная замена источника факта во всех предварительных экранах.
- Локальный статус проведения документа не равен отдельному серверному ACK. Существующая очередь облачной синхронизации не заменена новым протоколом.
- Серверное разделение прав на общий SQL payload (F09) не исправлено этим UI/расчётным пакетом. Для него нужна отдельная серверная реализация с негативными тестами ролей.
- История ставок с датой действия, подтверждение отсутствий по конкретным датам, договорные правила Gross/Net, налоги и порядок доплат требуют отдельных согласованных правил. Налоговые ставки в этом пакете не менялись. Экспорт 1С по-прежнему требует проверки бухгалтером перед импортом.
- Терминал явки ещё не является автоматическим источником оплачиваемых часов. Порог 24 часа используется только для пар вход/выход; это не утверждённая длительность смены.
- Новые документы отмены с физическими снимками сохраняются как доказательство для синхронизации. Их число может превышать прежний ориентир 400; нужна будущая архивная стратегия без удаления действующих доказательств.
- Сочетание «Отменить»/Ctrl+Z в истории кодов не охватывает same-code подтверждение; его можно убрать общей отменой черновика. История снимков сохраняется для проверки, отдельного экрана выбора старой версии пока нет.
